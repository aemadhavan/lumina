Engineering Contract

The Non-Negotiable Core Thesis

Why standard LLM wrappers fail in enterprise and how LUMINA enforces guarantees.

1. Grounding as Strict Arithmetic

Most AI search engines cite snippets or hallucinate links. In LUMINA:

  • Snippet synthesis is forbidden: Content is synthesized only from full fetched page text or verified document chunks.
  • Zero fabricated citations: Every [n] in generated text must resolve to exactly one fetched source in the request.
  • Arithmetic validation: Checked via exact normalized token overlap. A judge model is never trusted to grade citations.

2. Fail Loud — No Silent Fallbacks

The costliest production bug is a try/catch that returns plausible text:

  • Live Translate lesson: Silent catch blocks can serve broken or hallucinated English for weeks with green 200 OKs.
  • Honest upstream failure: If a model or search provider throws, the run terminates immediately with terminated: "error" and returns HTTP 502.
  • Traceable errors: Every failed tool execution explicitly reports { ok: false, error: "..." } to the agent state.

3. Unbounded Loops are Outages

An agent loop without determinism is a production countdown:

  • Hard Tool Caps: Quick mode capped at 8 tools; Deep mode capped at 24 tools.
  • Hard Time Caps: 90 seconds (quick) / 240 seconds (deep) strictly enforced by the server harness.
  • Honest Partial Answers: If a cap is reached, output states terminated: "cap" rather than fabricating a finished status.

4. Metadata Precedes Text

Eliminating UI stutter and rendering stalls:

  • Order: trace → sources → token → done
  • Immediate Chip Hydration: Citations arrive before the first character of text streams so the client never renders dangling chips.
Distributed Topology

Six-Component Decoupled Architecture

Strict separation of edge routing, agent reasoning, background processing, and persistence.

1. Web SPA
React 18 + Vite deployed on Vercel. Handles streaming token rendering, citation chip popovers, spaces management, and the /evals live scorecard. Zero credentials.
2. Edge Gateway
Express reverse-proxy on Railway (:8787). Public edge boundary: enforces CORS, generates/validates X-Request-Id and X-User-Id, Zod validation, and unbuffered SSE pass-through with 2KB warmup padding.
3. Agent Core
Internal Express service (:8000). Completely private. Holds API credentials, executes ReAct loop (web_search, fetch_page, recall_memory, save_memory, plan_research), and enforces budget caps.
4. Ingestion Worker
Asynchronous Node worker polling MongoDB jobs. Parses PDFs from GridFS, segments chunks, computes embeddings, and performs read-your-write vector verification.
5. MongoDB Atlas
Unified persistence: Relational collections (threads, messages, memories, spaces), GridFS binaries, and Vector Search index over chunks.
6. Ephemeral Caches
Two-tier search cache: In-process LRU + MongoDB searchCache (24h TTL, SHA-256 keyed). Append-only run logs in runs/<requestId>.json.

Autonomous Research Loop

Deep Research: Decomposition & Fan-Out

How LUMINA turns an ambiguous prompt into structured multi-domain findings.

PHASE 1

Decomposition

Agent calls plan_research. Generates 3–6 mutually exclusive, collectively exhaustive sub-questions with clear rationale.

PHASE 2

Sub-Tree Fan-Out

Iterates across each sub-question. Executes web search and full-page scraping, tracking subQuestion IDs on all traces.

PHASE 3

Source Merging

Deduplicates overlapping URLs and chunks. Generates contiguous numbering [1..N] preserving sub-question attribution.

PHASE 4

Synthesis

Streams structured markdown: Direct answer, sub-question sections, and open unknowns. Streams sources before tokens.

Persistence & Context

Multi-Thread Memory & Decoupled RAG

Persistent preferences without session amnesia; crash-safe document vectorization.

🧠 Long-Term Semantic Memory

Thread history disappears when a thread closes. Memory survives across all conversations:

  • Explicit Writes Only: Agent calls save_memory only for permanent facts (e.g. user preferences, tech stack).
  • Semantic Retrieval: recall_memory uses Atlas Vector Search on memories.embedding filtered by userId.
  • Clean Transparency: GET /memory inspects everything; DELETE /memory/:id immediately purges effect.

📄 Decoupled Document Ingestion

Sync parsing in request paths stalls Node.js. LUMINA decouples ingest completely:

  • Instant 202 Accepted: POST /spaces/:id/documents saves to GridFS, creates a job, and returns in milliseconds.
  • Crash-Safe Worker: Atomic findOneAndUpdate with 5-min lease timeout. Sweeper resets stale crashed jobs.
  • Read-Your-Write Probe: Document status only flips to indexed after a vector query successfully retrieves its chunks.

Architectural Decisions

Engineering Trade-offs Answered

Deliberate choices made to balance complexity, cost, and reliability.

Atlas Vector Search vs. Dedicated DB (Qdrant)

Consolidated document metadata, relational threads, and vector embeddings in a single MongoDB cluster. Eliminated dual-database sync complexity and cross-system transaction failures, while managing Atlas M0 index sync lag via read-your-write probes.

MongoDB TTL Collection + LRU vs. Redis

Built a two-tier in-process LRU backed by a MongoDB TTL collection rather than deploying a standalone Redis cluster. Lowered monthly operational spend and removed an external failure point with minimal cache lookup overhead.

Bounded ReAct Loop vs. Multi-Agent Swarms

Enforced hard deterministic caps on tool calls and wall-clock execution over unpredictable autonomous swarms. Delivered rock-solid latency bounds and predictable sub-cent operational costs.

Local PDF Extraction vs. Cloud OCR

Lightweight Node extraction runs entirely inside the local background worker process. Zero external API cost or latency penalty for textual PDFs, keeping document ingestion fast and free.
